# Independent word recognition in speaking review

The operator explicitly requested recognition without reference text for all seven speaking types, and accepted the existing synthetic reference bank, labelled Reference pronunciation. Recognition, segmentation, sound grading and the optional prompt diff are distinct stages. No learner audio or derived text leaves the device.

`facebook/wav2vec2-large-960h-lv60-self` revision `54074b1c16f4de6a5ad59affb4caa8f2ea03a119` is a frozen public Apache-2.0 audio-only recognizer, independently pinned by `recognition_model.py`. It replaces the former base recognizer after the recognition investigation in issue150; it does not replace the v3 phonetic model. The source checkpoint is hash verified before local loading. Dynamic per-channel INT8 MatMul/Gemm weights retain float32 convolution and other operations, without fitting. The derived encoder is 356,158,757 bytes split into <=48 MiB files. Greedy character CTC supplies words, confidence and estimated boundaries from audio alone, without a dictionary/language-model prior, prompt, hotwords or answer key. The four retained accent controls compare Python, exported CPU ONNX and browser WASM transcripts; this establishes compatibility, not human learner word-error validation. See [ADR-0001](../docs/adr/0001-use-a-compact-self-trained-audio-only-recognizer.md) and the [upstream model card](https://huggingface.co/facebook/wav2vec2-large-960h-lv60-self).

A compact 124,082-word pronunciation dictionary contains locally generated US/GB eSpeak phonetic variants for CMUdict spellings and current fixed-question words. CMUdict vocabulary license is bundled. Australian and Indian sounds remain equally accepted by the unchanged v3 acoustic reference bank; dictionaries and the recognizer do not establish equal recognition accuracy across accents. Unsupported phonetics are omitted. Recognized words outside the dictionary, low recognizer confidence (<0.4), failed alignment or uncertain sound evidence receive no invented grade.

The worker keeps 20-second owned recognition spans for at most 45 seconds between the first and last active audio (including trim context), and uses 10-second spans for longer active speech. Both retain one second of context on either side, keeping words by midpoint. Silent window edges are trimmed with 200ms of acoustic context, preserving original recording offsets; a long silent tail does not force shorter recognition context. The recognition session is released before loading v3. Phonetic grading always retains its original 20-second owned spans and at most 22-second context. Each word’s audio interval selects phonetic encoder frames for dictionary-based local alignment and the unchanged trained sound projection/reference-bank comparison. Word and syllable timestamps are estimates. Up to 125 seconds is accepted for open speaking tasks; continuous speech must complete inside the unchanged 300-second production worker deadline. Legacy expected-text and isolated syllable calls remain bounded to 45 seconds. Cancellation terminates worker ownership; silence/noise checks remain in place. Multiwindow boundaries and difficult learner speech remain evaluation risks.

The independent result adds `recognition: {modelId, recognizerSha256?, recognizerRevision?, decoder?, windowSeconds?, words}` to the compatible pronunciation record. New results identify the exact encoder/upstream revision and `greedy-ctc-adaptive-v1` decoder, with the chosen 10/20-second span in `windowSeconds`. Older independent results remain readable and are not silently rescored. Each word has spelling, occurrence index, start/end, confidence and recognized/uncertain/unsupported state. Only the existing IndexedDB queue persists it. An upgrade stores its result separately as `speechAssessment` and leaves `pronunciation` intact; no transcript or grade enters the localStorage index. All speaking types use the same review owner and effort-only retry XP contract. The optional prompt edit-distance diff changes display only; it cannot alter recognised words, times or grades.

The bundled word-audio library derives 998 word entries from retained training examples (no held-out/test voice) and existing original review examples. Each clip retains source take/hash, synthesis/listening status, accent and estimated syllable bounds. Several available accents remain available as source references; the UI selects a matching label/count when possible. These are contextual word excerpts, not new standalone studio takes. Whole-word playback remains available for another pronunciation pattern, but a syllable reference is shown only when its pattern matches the learner’s scored labels. No new audio is synthesized and no paid request is made. The library is smaller than the phonetic dictionary: an absent reference recording is shown explicitly, with learner playback retained. Missing clips never silently substitute a prompt lookup, browser/OS voice or cloud provider. Human listening/learner pronunciation validation is pending; “gold standard” is not claimed.

Obtain the public checkpoint and tokenizer/configuration files from the exact upstream revision into an ignored local directory; verify the weight SHA specified in `recognition_model.py`. The source is not shipped. For an encoder-only rebuild retaining existing pinned dictionary/reference derivatives, pass `--encoder-only` to `export_recognition.py`; it verifies all retained assets and does not require re-exporting word references.

The two exporters write pinned manifests to public and source, with complete hashes, source identities and exporter digests. Run them in that order. Browser controls stay in ignored `artifacts/word-recognition-export/` with distinct `control-` names; reference temporary PCM uses `reference-` names. Raw corpus, Python dependencies, source checkpoint files and credentials remain outside the publish artifact. The recognition pack includes the compact encoder plus the unchanged dictionary and reference audio; decoded and transfer sizes are pinned separately in its manifest; automatic preparation remains in the notification bell. Both packs share the verified scope-specific model cache, separate from the ordinary offline app bundle.

Rollback is reverting the recognition assets and integration; the unchanged v3 bank and original recordings are retained. Older readers ignore additive result fields. No model benchmark, synthetic classification statistic, transcript match or content diff is a validated learner pronunciation/fluency/exam score.

## Lossless browser transport and isolated retries

After regenerating the browser comparison and recognition packs, run `node scripts/pack-models.mjs`, then `npm run validate:comparison`. The packer shuffles binary byte pairs and uses gzip; JSON uses `.packed` sidecars to avoid static hosts applying HTTP gzip decoding automatically. Transport hashes and decoded hashes are both pinned. Decoded encoder hashes, model identity, head, bank and calibration remain unchanged; existing verified decoded caches remain reusable. `totalDownloadBytes` reports transfer size separately from `totalBytes`.

Word-reference index/audio files can be fetched and verified independently while automatic preparation continues in the header. Warm availability uses validated-file receipts; every inference/reference read checks the decoded SHA again. Corrupt reads remove their cache entry for a real notification retry.

Retries use word-local phonetics with compatible synthetic syllable clips, processed through the browser's native recording codec, trimmed and padded equally, with ±10 ms reference phases. The existing projection compares each phone against its nearest compatible reference, giving each accent equal validity. Every phone requires confidence >=0.03; incomplete/uncertain reference or learner alignment returns no numeric grade. These controls establish codec-path consistency and wrong-sound rejection for the bundled examples, not human pronunciation validity. Original session scoring and saved evidence do not change. No audio leaves the device.

Recognition chunks use the versioned `recognizer-lv60-int8-` filename prefix. The shared model-cache identity and unchanged phonetic/dictionary/reference URLs remain stable, while a prepared older tab keeps its original decoded recognizer entries. New preparation must not overwrite those old cache keys. An older tab with an incomplete pack may need an ordinary app update after publication; do not activate one during an attempt.
