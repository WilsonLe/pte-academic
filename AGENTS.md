# PTE Studio

An independent, beginner-friendly PTE Academic practice PWA. All learner-facing content is original and versioned in Git. There is no backend, CMS, account, cloud runtime AI, analytics, external font request or runtime provider credential.

## Playtest

When asked to “playtest”, run a “playtest session”, or act as a student and suggest improvements, read [agents/playtest.md](agents/playtest.md). Use the visible built-in browser, report observed learner friction, and favor less screen clutter with details on demand. Follow the guide's implementation/retest steps when fixes are requested.

An explicit request to run an “autopilot playtest” selects the guide's [single-cycle mode](agents/playtest.md#autopilot-playtest-one-cycle): playtest, implement observed improvements, retest, independently review, pass merge gates, merge that cycle's PR to `main`, then verify the merged revision. That invocation supplies merge authority for that cycle only; ordinary playtesting retains its existing boundaries.

## Architecture

- Keep the learning workspace minimal: desktop icon sidebar and header, mobile header and a three-tab footer with text below icons: Practice, Learn, History. Keep question types, sections and mocks within Practice, and utilities in the header. Use accessible names and tooltips for icons; keep beginner guidance in animated collapsibles/accordions, success feedback in Sonner, and honor reduced motion. The operator subsequently requested a more playful, gamified design: allow purposeful violet/lime game cards, XP, streaks, badges and finite celebration motion. The operator then requested larger game UI without a scrolling dashboard: use a viewport-sized play screen, large controls, button-selected progress/collection screens and paged practice catalogues, guidance, history and review. Learn topic cards and article text scroll instead of paginating. Measure reading pages against the actual font/panel; never clip text to force a fit. The operator subsequently requested disabled zoom and no app/document scrolling: keep the outer viewport fixed, suppress app-controlled zoom gestures/shortcuts, and preserve contained content scrolling in Learn, very short windows or browser accessibility overrides. Keep the timed runner focused and avoid marketing heroes or repeated explanatory copy.
- Use practice/session language in learner-facing copy despite the playful visuals; retain the requested “Start daily quest” action. History uses compact cards with the heading “Sessions.”; Learn uses “About PTE.” Single-page pagers are hidden. Do not add learner-facing history deletion controls or dialogs. Do not restore the removed header install/offline/info controls, beginner footer or sidebar privacy icon.
- Keep required speech-model preparation in the header notification bell and its popover list, including download progress and error/retry details; do not show a preparation banner in the workspace.
- `src/routes/` owns typed TanStack Router routes; `src/routing.ts` owns shared screen identity and navigation destinations; `src/router.tsx` creates the Start router and local Query provider; preserve basename-aware real paths, history deep links, back/forward and reload recovery. `src/PracticeSession.tsx` owns route-scoped preflight/run lifecycle. Shared playback lives in `src/components/AudioPlayer.tsx` using existing shadcn controls and practice tokens; timed prompts retain Runner authority and one-play rules.
- `src/Review.tsx` owns saved review panels; `src/review-content.ts` owns labelled source blocks and example/outline labels. `ReadingPages` packs labelled blocks using the actual rendered font/panel. Preserve numbered gaps/paragraphs, selected/missed choices and written/heard word positions. Writing examples are alternatives; essay support is a planning outline. The single Feedback surface owns replayable source audio, deduplicated source text and learner playback.
- `src/FriendlyFeedback.tsx` and `src/review-diff.ts` own clickable non-speaking comparisons and neutral legacy-transcript review. Keep rationale, source and writing alternatives behind selection; do not restore default Your order/Correct order/Why stacks. Reorder uses authored `orderExplanations` for every expected position, explaining both available neighbours and the opening/conclusion role. Speech keeps independent acoustic grades and word dialogs; a prompt omission may explain recognition uncertainty without starting a syllable retry or awarding XP.
- Review keeps one response panel, with a differing answer key inline for text answers. Keep only question-specific feedback here; general tips belong in Learn. Use shared `ReadingPages` to deduplicate and pack related text across guidance, details and review; open question guides with Instructions. Keep media status in one place and omit completed audio-only panels. Put question navigation beside the heading, and show save rewards once through Sonner. Progress opens through the header and Practice through the main navigation; do not duplicate those actions in the game hub. Achievements opens from History with a visible label; do not add trophy shortcuts to Practice or Progress. The workspace header stays sticky during scrolling.
- Saved reviews have one Feedback surface without a tab selector, Your response/Prompt tabs, Compare again, Self-review button or help dialog. Include only questions with saved responses/evidence and hide the question pager for a single item; zero responses has an empty state. Speaking tasks show recognised words in a paged acoustic diff (with optional prompt omissions/substitutions computed afterward) with green/yellow/red on the authored syllable letter groups (neutral for uncertain/unscored groups; no number/question-mark chips), with similarities available in the word detail, automatic initial grading, paired source/learner playback and word-selected syllable retry dialogs. Retry audio/grades are ephemeral and cannot overwrite the original session. Other response kinds combine response/key comparisons, source and specific feedback without unsupported scoring. Header model notifications remain the sole preparation UI. Home has no XP information button, Sections has no information control, Types has no Clear filters button, and preflight has no Practice details accordion; its third rule explains leaving/refreshing ends the attempt.
- `src/components/CardsList.tsx` owns responsive card grids and conditional pagination for catalogues, history, practice modes and achievements. Use its sizing options instead of independent column/row breakpoints; keep text readable and empty/single-page lists free of pagination.
- Keep the five playtest refinements compact: daily preparation reuses its question-count chip for an optional guide/timer preview; do not add default preparation prose. ReadingPages prefers complete numbered paragraphs and sentences before splitting oversized units, using the actual panel fit. Review counters distinguish Question from Feedback within the existing control; the runner's last action explicitly finishes practice.
- Writing review keeps one complete neutral response in measured ReadingPages, preserving paragraph breaks; explanation, writing checks and alternatives/planning outline open once through Details. Do not pre-split writing into fixed-character response cards. Label runner clocks Section time remaining and Question time remaining. Truncated question-guide header titles expand through their keyboard/touch popover without adding default title copy.
- TanStack Start uses SPA mode, a root `ClientOnly` outlet and a client-only workspace route. Keep the document hydration boundary so static deep links do not hydrate an app against empty shell markup. Only the public document shell renders at build time. Publish only the client files copied into `dist/` by `scripts/publish-static.mjs`; `.start/server` is build-only. Preview uses `vite.static.config.ts` to exercise actual static hosting. Never introduce runtime server functions or serialize learner data into the shell.
- Keep production JavaScript below the default 500 kB chunk budget; both builds verify the published artifact. React has its own reusable chunk. The comparison worker uses explicit pinned `wasmPaths` with ONNX's external-WASM export condition and the WASM-only entry. Keep it standalone so its complete runtime assets remain covered by the existing preparation/on-demand cache lists.
- `src/queries.ts` owns TanStack Query options for the local history index and progress profile plus save/clear mutations. Use `networkMode: "always"` and no automatic retries; the existing storage queue remains the only persistence authority. Cancel stale reads before publishing committed snapshots. Keep response/recording review lifecycle outside the query cache and reset completed save mutation state.
- Runner uses TanStack Form for answer values and an immediate ref for deadline/record-stop callbacks. Keep skips and blank submissions legal, with no live hints/answer validation.
- React + TypeScript + Vite; use the installed lockfile and `npm ci` (Node 22.12+).
- Tailwind v4 and shadcn's default Nova/Base UI/neutral preset. Preserve generated theme tokens in `src/style.css` and configuration in `components.json`. Learning pages use these defaults; the exam surface has isolated `.exam` styles for test conventions. Shared practice accents are scoped by `.practice-ui`, including portalled dialogs and notifications. Style Buttons through their variant/size metadata: Base UI render composition can replace `data-slot`.
- `content/*.json` is the source of truth, imported into the static build. `src/content.ts` owns schemas and feedback logic. Read `content/AGENTS.md` before editing content.
- `src/Runner.tsx` owns forward-only progression, wall-clock deadlines, audio/recording lifecycle and preflight. `QuestionInput.tsx` owns response controls. Never show hints, transcripts or answer keys inside an active test.
- Game progress in src/progress.ts rewards saved effort, never proficiency: 10 XP per different answered question per local day, plus 30 at three; levels every 150 XP. src/GameHub.tsx owns the game surfaces. Save profile and attempts atomically through the storage queue; automatic speech scoring and passive review cannot award XP. The operator subsequently authorized 5 XP for a completed syllable retry once per speaking question/word occurrence/syllable per local day, independent of its score; silence/cancel/failure earn none. `saveReviewReward` uses the existing queue and a retained-attempt/progress transaction, with compatible `reviewDay`/`reviewed` fields. Review rewards do not advance daily quest counts or practice streaks. There is no learner-facing clear-history action; internal storage clearing retains its atomic progress reset contract. Retaining 10 attempts must not erase earned XP or badges.
- localStorage stores a small attempt index. IndexedDB v2 stores responses/audio Blobs and a separate progress profile, with 10 retained attempts. Preserve v1 records on upgrade; an old v1 opener cannot downgrade a v2 database. Cache Storage stores the static offline pack. No learner data is sent to a provider.
- The generated shadcn helper stylesheet is vendored unchanged in `src/vendor/shadcn.css` with its MIT license. Use `npx shadcn@latest` to add components; do not ship its scaffolder and archive-processing dependencies in the app.
- `scripts/build-sw.mjs` precaches only build output, scopes cache cleanup by registration scope and serves local media byte ranges. Do not automatically activate updates during an attempt.

## Content and product boundaries

- Assume learners know nothing about the test. Explain terms before using abbreviations.
- Provide all three modes: question type, section and full mock.
- Do not refer to or link official Pearson material; this is an explicit operator request. Do not copy official questions, instructions, screenshots or branding. Preserve brief independent-practice and scoring limitations.
- Do not claim exact live-test pixel parity or validated 10–90 scores. The current runner's fidelity limits are listed in `docs/test-fidelity.md`.
- OpenRouter models/keys are authoring-time only; never add client-side provider calls. Whisper/Transformers.js transcription has been removed at the operator's request in favor of the in-house comparison model. Do not restore automatic transcription or word-match/pace feedback. The operator subsequently explicitly requested independent audio-only word recognition for every speaking activity, including activities without reference text. This supersedes the earlier ban on automatic transcription, using pinned local wav2vec2 recognition via the existing ONNX worker rather than restoring Whisper/Transformers.js. Existing saved transcripts remain readable.
- The operator subsequently authorized using accepted blended-English v3 for local Read Aloud/Repeat Sentence syllable grading and explicitly requires its automatic download (not opt-in). `src/speech/comparison-*` owns its pinned, hash-verified model/runtime cache and worker. Keep all four reference accents equally valid, null uncertain scores, bounded inference windows, cancellation and reference-similarity/not-correctness disclosures. Audio-only review supports at most 125 seconds using overlapping <=22-second windows; legacy prompt-aligned and syllable retry calls retain the 45-second limit. Do not substitute transcript word matching for a grade. Derived browser model weights are committed; raw training audio/features/credentials remain ignored. No learner recording is uploaded.
- Persist syllable grades through `savePronunciation` in the existing IndexedDB queue. `legacy-transcription.ts` and the unused queued `saveTranscription` API preserve old transcript storage compatibility without an inference runtime. Never put them in the localStorage index or recreate cleared/pruned attempts. Speech worker/WASM assets cache on demand; model cache is separate from the ordinary offline pack.
- Use original black/white line-art branding inspired by the operator's rounded-square app icon references. `public/icon.svg` is the vector master; run `python3 scripts/generate-icons.py` after an icon change.

For repository changes: issue before implementation, isolated feature branch, focused current-candidate checks, linked draft PR, one independent review. Merge and deployment require authority; an explicit autopilot playtest invocation grants the bounded merge authority described in the playtest guide.

Syllable letter colouring uses `content/syllable-spelling.json` and `src/speech/syllable-display.ts`. Preserve complete original spelling/case/contractions/punctuation; these are display groups for syllable scores, not model-derived per-letter grades. Keep coverage for every current fixed-speech candidate variant in `validate:comparison`; unknown mappings stay neutral.

Independent speech review uses `recognition-core.ts` and the pinned `recognition-manifest.json`: audio-only character CTC words/times precede word-local v3 phonetic grading. Prompt text must never enter recognition, word segmentation or original-result grading; it is only a later display diff. `training/export_recognition.py` exports the frozen public recognizer and offline word lexicon; `export_word_references.py` derives global word audio from training takes and original review examples, excluding held-out/test voices. Reference audio has finite coverage and pending listening review; never call it human gold or substitute a prompt/OS/cloud voice for a missing clip. All model assets are hash verified and prepared through the header notifications. Automatic upgrading of saved prompt-aligned feedback keeps it in `pronunciation` and stores the new result separately as `speechAssessment`; original recordings and legacy transcripts remain intact.

Issue #53 recovery uses a public-shell bootstrap guard independent of hashed JavaScript. Broken older-shell rescue must complete the new cache and check all scoped client URLs before activating; never await `WindowClient.navigate()` inside activation (navigation waits for activation). Coherent updates remain manual. Retain learner storage/model caches.

Model transports are lossless (`scripts/pack-models.mjs` after both exporters). Pin transport and decoded hashes separately; decoded caches retain the existing model IDs. Warm preparation may inspect validated receipts, but actual reads must verify decoded SHA and evict corrupt entries for retry. Word-reference files can prepare independently. Missing/weak reference or learner evidence stays uncertain. Keep original-session scoring unchanged.
